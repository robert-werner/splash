### 1. **Capacity Planning Происходит ДО Оптимизаций**

Context length вычисляется в `RuntimeResources.mm` на основе:
- Размера модели (27B параметров)
- Memory limit (18 GB)
- KV cache размера (фиксированный расчет)

**Phase 2+3 оптимизации работают в runtime, НЕ влияют на init-time capacity.**

### 2. **Int4KvCache Не Меняет Allocation**

Текущая реализация (1b855d0):
- Metal kernels созданы ✅
- Runtime checks добавлены ✅
- **НО:** quantization НЕ меняет `KvPool` allocation size
- Capacity planning видит FULL float32 KV size

**Нужно:** Изменить `kvBytesPerToken` в KvPool constructor:
```cpp
if (config.int4KvCache) {
  kvBytesPerToken /= 2;  // INT4 = 2× compression
}
```

**Ожидаемый gain:** ~2× context (180K → 360K)

- Capacity planning уже завершен

**Gain:** ~3% (5-7K tokens из 180K)

### 4. **VisionConditional Не Применим**
